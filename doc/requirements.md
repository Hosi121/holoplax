# 製品の目的と方針

主対象は個人のセルフマネジメント。仕事と生活のタスクを集め、計画し、進め、振り返るときの
認知負荷を減らす。workspace は文脈の分離と、小さなチームでの共有に使う。

AIの下準備とアジャイル運用を組み合わせ、継続を支えながら成果を増やす。
北極星は長期に維持できるベロシティ。タスク進行量、Sprint / PBI の実績を見るが、
短期のポイント増加だけで価値を判定しない。

## 現在の利用経路

| 目的 | 画面 |
| --- | --- |
| 小さな仕事をAIに任せる | `/delegate`（`/` の遷移先） |
| 集めて整理する | `/backlog`、インテーク |
| 計画して進める | `/sprint`、`/kanban`、フォーカスキュー |
| 振り返る | `/review`、`/velocity` |
| 自動化・接続・文脈を管理する | `/automation`、`/settings`、`/workspaces` |
| 運用管理 | `/admin/users`、`/admin/ai`、`/admin/audit` |

タスク管理には階層・依存・繰り返し・チェックリストを使い、容量はポイントで管理する。
AIは見積もり、分割、優先付け、文章の成果物作成を支援する。
手入力・メモ・Discord / Slack から取り込み、MCP からも同じタスク操作を使える。

## 変更時に守ること

- 認証と workspace の権限を、画面だけでなく API と共有ユースケースで確認する。
- 計画と実行状態を分け、編集・削除後も実績と判断履歴を残す。
- 提案の同意・修正・拒否を扱い、人間の希望を推定より優先する。
- 送信・予約・購入などに実行権限があると誤認させない。実行AIの範囲は [委譲の契約](personal-delegation.md) に従う。
- 主に日本語・PC での利用を想定し、各画面で次に判断する内容を絞る。

カレンダー・メール取り込み、通知、高度な予測は将来の検討範囲。
採用する場合は対象と完了条件を決めてから実装する。
現在の制約は [課題](issues.md)、内部の規則は [ドメイン](work-item-domain.md) を参照。
